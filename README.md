# Ценовой ориентир — обоснование НМЦД

Сервис по описанию планируемой закупки находит сопоставимые предложения в открытых источниках,
приводит цены к единице измерения закупки, исключает несопоставимые и аномальные предложения и
считает начальную (максимальную) цену договора методом сопоставимых рыночных цен. На выходе —
отчёт, по которому расчёт можно повторить вручную: каждая цена со ссылкой и датой получения,
каждое решение о включении или исключении с причиной, формула с подставленными числами.

Все числа считает детерминированный код по заданным правилам, результат повторяется при каждом запуске.

## Требования к окружению

| Вариант | Что нужно |
|---|---|
| Docker (рекомендуется) | Docker 24+ с Compose v2, доступ в интернет к источникам |
| Без Docker | Node.js 20+ (проверено на 26), npm |

База данных не нужна: отчёты хранятся JSON-файлами в каталоге `data/`.

## Запуск в Docker

```bash
docker compose up --build -d
```

Интерфейс: <http://localhost:3000>. Проверка готовности:

```bash
curl http://localhost:3000/api/health
```

Остановка (отчёты сохраняются в томе `nmcd-data`):

```bash
docker compose down
```

Остановка с удалением сохранённых отчётов:

```bash
docker compose down -v
```

Каталоги `config/` и `certs/` подключены в контейнер только для чтения: источники и правила
меняются правкой JSON и перезапуском (`docker compose restart`), образ пересобирать не нужно.

## Запуск без Docker

```bash
npm ci
```

```bash
npm start
```

Остановка — `Ctrl+C`. Тесты:

```bash
npm test
```

Расчёт из командной строки (без сервера):

```bash
node scripts/cli.js "Бумага офисная А4, плотность 80 г/м2, пачка 500 листов, белизна не менее 146%" --qty 200 --unit упак
```

Проверка одного источника:

```bash
node scripts/try-source.js etm "кабель ВВГнг 3х2.5"
```

## Переменные окружения

Все переменные необязательны; образец — [.env.example](.env.example).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт HTTP-сервера |
| `HOST` | `127.0.0.1` (в образе `0.0.0.0`) | Адрес, на котором слушает сервер |
| `DATA_DIR` | `./data` | Каталог отчётов (`reports/`) и снимков ответов (`snapshots/`) |
| `CONFIG_DIR` | `./config` | Каталог `sources.json`, `rules.json`, `cpi.json` |
| `SNAPSHOT_MODE` | `off` | `record` — сохранять ответы источников; `replay` — считать по сохранённым ответам без сети |
| `EXTRA_CA_HOSTS` | `.gov.ru` | Суффиксы хостов, для которых действуют сертификаты из `certs/` |
| `BIND` | `127.0.0.1` | Адрес для Docker Compose. На сервере задайте `0.0.0.0` |

## Настройка без изменения кода

| Файл | Что настраивается |
|---|---|
| [config/sources.json](config/sources.json) | Список источников, включение и отключение, параметры адаптеров, единица продажи по умолчанию |
| [config/rules.json](config/rules.json) | Пороги сопоставимости, допуски, НДС, срок давности цен, правила выбросов, порог коэффициента вариации, минимальное число цен, приоритет источников, синонимы названий характеристик |
| [config/cpi.json](config/cpi.json) | Индексы потребительских цен Росстата для приведения цен прошлых периодов |
| `certs/*.pem` | Дополнительные корневые сертификаты для хостов `.gov.ru` |

Новый источник — один модуль `src/sources/<id>.js` и одна строка в `sources.json`
([инструкция](docs/ADAPTERS.md)). Снимок действующих правил записывается в каждый отчёт.

| ГИСП (gisp.gov.ru) | государственный каталог | закрыт JS-проверкой на всех адресах |
| ЕАТ «Берёзка» (agregatoreat.ru) | агрегатор торговли | закрыт JS-проверкой на всех адресах |

Защиту источников сервис не обходит: заблокированный источник показывается в отчёте как
недоступный с причиной, расчёт продолжается по остальным. Адаптеры Комуса, ГИСП и «Берёзки»
проверены только на страницах блокировки; их разбор успешных ответов написан по предположению и
на реальных данных не проверен. Цены из недоступных источников можно добавить вручную — они
участвуют в расчёте наравне с найденными.

## Как считается цена

1. **Разбор описания.** Наименование, ключевые слова, существенные характеристики (число + единица,
   формат, типоразмер, «не менее / не более»), количество, единица измерения, фасовка.
2. **Поиск.** Источники опрашиваются параллельно, каждый со своим лимитом времени.
3. **Проверка и дубли.** Предложение без цены, ссылки или даты получения исключается; дубли
   определяются по идентификатору, ссылке и совпадению названия, цены и поставщика.
4. **Сопоставимость.** Каждая существенная характеристика проверяется по характеристикам и названию
   предложения: совпадает, не совпадает, нет данных. Исключаются: другой предмет, сопутствующий товар
   («для …»), другая модель или артикул, несовпадение существенной характеристики, недостаток данных
   (подтверждено меньше 75% существенных характеристик).
5. **Приведение цен.** Единицы измерения (г → кг, км → м), фасовка (бухта 100 м, коробка 5 пачек,
   набор 4 шт), НДС для цен «без НДС», индексация по ИПЦ для цен старше 6 месяцев; цены старше
   36 месяцев не используются. Каждая поправка записывается с исходными числами.
6. **Аномальные цены.** При 5 и более ценах — правило межквартильного размаха
   `[Q1 − 1,5·IQR; Q3 + 1,5·IQR]`, причём цена исключается, только если ещё и отличается от медианы
   более чем на 20%; при меньшем числе цен — отношение к медиане `[0,5·Me; 2·Me]`.
   Правило применяется повторно к оставшимся ценам (до трёх проходов), чтобы очень далёкая цена не
   прикрывала следующую аномальную; каждый проход записывается в отчёт.
7. **Приоритет источников.** Реестр контрактов ЕИС — главный источник. Если сопоставимых цен из
   приоритетных источников (ЕИС, государственные каталоги, агрегаторы, введённые КП) не меньше трёх,
   цены магазинов и каталогов в расчёт не берутся и помечаются «ниже по приоритету источников»;
   при нехватке приоритетных цен используются все. Отключается параметром `priority.preferPrimary`.
8. **Расчёт.** `V = σ / <ц> × 100%`, `σ = √(Σ(цᵢ − <ц>)² / (n − 1))`, `НМЦД = v × <ц>`
   (Методические рекомендации, приказ Минэкономразвития от 02.10.2013 № 567, пп. 3.19–3.21).
   Если цен меньше трёх или `V > 33%`, цена **не формируется** — сервис сообщает, чего не хватает.
   Цены не удаляются ради достижения нужного коэффициента вариации.
9. **Ручные правки.** Любое решение можно изменить в отчёте; расчёт повторяется по тем же правилам,
   правка фиксируется в отчёте.

## API

| Метод и путь | Назначение |
|---|---|
| `GET /api/health` | Состояние сервиса |
| `GET /api/sources` | Источники из конфигурации |
| `GET /api/rules` | Действующие правила |
| `POST /api/calculate` | Расчёт. Тело: `description` (обязательно), `quantity`, `unit`, `okpd2`, `region`, `sources[]`, `manualOffers[]` |
| `GET /api/reports` | Последние расчёты |
| `GET /api/reports/:id` | Отчёт в JSON |
| `GET /api/reports/:id/docx` | Отчёт-обоснование в DOCX |
| `POST /api/reports/:id/recalculate` | Пересчёт с ручными правками: `{ "exclude": [номера], "include": [номера] }` |

```bash
curl -X POST http://localhost:3000/api/calculate -H "Content-Type: application/json" -d "{\"description\":\"Кабель силовой ВВГнг(А)-LS 3х2,5 мм2, напряжение 0,66 кВ\",\"quantity\":500,\"unit\":\"м\"}"
```

## Воспроизводимость

- Каждый отчёт сохраняется в `data/reports/<id>.json` со всеми исходными данными, решениями и
  снимком правил; пересчёт с правками не обращается к сети.
- `SNAPSHOT_MODE=record` сохраняет ответы источников, `SNAPSHOT_MODE=replay` повторяет расчёт по ним
  без сети — с исходными датами получения данных.

## Ограничения

- ЕИС: наличие штрафов и пеней по контракту не проверяется (это видно в карточке по ссылке из
  отчёта); поиск идёт по тексту без фильтра по ОКПД2; поставщик в отчёт не выносится; характеристики
  КТРУ сопоставляются с требованиями по названиям и синонимам из `config/rules.json`, поэтому часть
  подходящих контрактов исключается как «недостаток данных», если названия характеристик расходятся.
- Таблица ИПЦ (`config/cpi.json`) заполнена данными Росстата с января 2022 по сентябрь 2026 года и
  обновляется вручную: новые месяцы дописываются из файла `ipc_mes_*.xlsx` со страницы
  <https://rosstat.gov.ru/statistics/price>. Месяцы, по которым индекс ещё не опубликован, учитываются
  без изменения цен, и это указывается в отчёте. Используется общий ИПЦ на товары и услуги, а не
  индексы по отдельным товарным группам.
- Сертификаты Минцифры из `certs/` действуют только для хостов `.gov.ru`; без них ЕИС показывается
  в отчёте как не настроенный источник.
- Разбор описания работает по правилам и рассчитан на товары с числовыми характеристиками; для работ
  и услуг автоматический поиск в подключённых источниках обычно ничего не находит.
- Условия поставки (доставка, регион, объём партии) в цене не учитываются: источники их не публикуют.
- Сервис не отличает оригинальные расходные материалы от совместимых, если это не указано в описании.
- Ставка НДС берётся из `config/rules.json` (22%) и применяется только к ценам, помеченным «без НДС».
- Сборка Docker-образа на машине разработки не проверялась (Docker не установлен); локальный запуск,
  тесты и расчёты на живых источниках проверены.
- Аутентификации нет: сервис рассчитан на запуск в доверенной сети (по умолчанию слушает `127.0.0.1`).

## План развития

1. ЕИС: фильтр по ОКПД2 и региону, проверка исполнения без штрафов и пеней, закупки по 223-ФЗ.
2. Автоматическое обновление ИПЦ из открытых данных Росстата по расписанию, индексы по товарным группам.
3. Загрузка ТЗ файлом (DOCX, PDF) и расчёт по нескольким позициям спецификации.
4. Справочник ОКПД2 и КТРУ для подсказки кода и обязательных характеристик.
5. Доступ к закрытым площадкам по официальным API и договорам вместо разбора страниц.
6. Учёт региона и условий поставки, запрос коммерческих предложений поставщикам из отчёта.
